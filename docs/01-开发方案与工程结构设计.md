# 01 · 双系统架构设计与技术选型

- 技术栈：.NET 8 / ASP.NET Core Razor Pages / SQLite / 原生 Win32 P/Invoke
- 工程形态：1 个解决方案 / 4 个工程 / 共用 1 套公共库
- 编译口径：`dotnet build` 全绿（0 警告 0 错误），`dotnet publish` 出单文件免安装 exe
- 文档版本：v1.0

---

## 一、设计结论

| 事项 | 结论 |
|---|---|
| 技术路线 | **.NET 8 自研主体 + 集成宽松许可开源组件**（Bareos / osquery 换皮路线已否决，理由见第二节） |
| 工程形态 | 公共库 + 三个应用工程，公共库被三端共同引用 |
| 数据层 | SQLite 单文件库，轻量 SQL 映射（不引入 EF Core，避免迁移开销） |
| 部署形态 | `--self-contained` 单文件 exe，目标机无需安装 .NET 运行时 |
| 虚拟机备份 | 抽象 `IVmBackupProvider` 接口 + 文档，不具备环境时降级为接口预留 |

## 二、技术选型：为什么否掉 Bareos / osquery

项目最初考虑以成熟开源产品为底座二次开发，实测后放弃。这一节的结论直接决定了"自研主体"的路线。

### 2.1 Bareos（原拟作备份底座）

| 维度 | 事实 | 判定 |
|---|---|---|
| 语言/形态 | C++，Director + Storage Daemon + File Daemon 三段式 | — |
| Windows 支持 | 官方**仅提供 File Daemon 客户端二进制**；服务端（Director/SD）为 Linux 取向 | ❌ |
| Windows 编译方式 | 官方 Windows 版由 **Linux + MinGW 交叉编译**产出，非 Windows 本地编译 | ❌ 与"可本地编译"要求冲突 |
| 许可证 | AGPLv3（强 copyleft） | ⚠️ 整体交付会传染 |
| 界面 | 老式 PHP WebUI，无法满足现代控制台观感 | ⚠️ |

> 一句话：**"两套软件可本地编译通过"这条要求，Bareos 在 Windows 上给不了。**

### 2.2 osquery（原拟作桌管底座）

| 需求项 | osquery 实际能力 | 判定 |
|---|---|---|
| 禁用控制面板 / 禁用 USB | 只读查询代理，**不做管控** | ❌ 需自研 |
| 文件增删改审计 | `file_events` 表**在 Windows 上不可用**（仅 macOS/Linux） | ❌ 需绕 Sysmon/USN |
| 日志查询界面 | 无，需另搭 Fleet（重型且界面为英文） | ❌ |
| 定位 | "把系统当数据库查"的采集器，不是管控产品 | ❌ 与需求错位 |

### 2.3 本机环境实测（选型依据）

| 工具链 | 状态 | 结论 |
|---|---|---|
| .NET SDK | **8.0.200（Runtime 8.0.11）已安装**，`dotnet build` 7 秒通过、`dotnet run` 正常 | ✅ **选它** |
| Go | 未安装 | ❌ |
| Node.js | 22.22.2 已安装 | 备用 |
| Python | 3.13.14 | 备用（辅助脚本） |
| Docker | 未安装 | ❌ |

主体代码自研，集成多个宽松许可（MIT / Apache-2.0 / BSD）开源组件，并交付 `THIRD-PARTY-NOTICES.md`

## 三、工程结构

### 3.1 目录

```
src/
├─ VaultGuard.Common/                公共库（类库）
│   ├─ Data/                         SQLite 连接与建表
│   ├─ Models/                       数据模型
│   ├─ Security/                     口令哈希 / 凭据加密
│   ├─ Util/                         路径 / 文件摘要
│   └─ Branding.cs                   品牌与版权（单一来源）
├─ VaultGuard.Backup.Web/            系统一：B/S 控制台（ASP.NET Core）
├─ VaultGuard.Endpoint.Server/       系统二：C/S 控制端（ASP.NET Core）
└─ VaultGuard.Endpoint.Agent/        系统二：终端代理（Windows 服务）
```

### 3.2 依赖关系

```
        ┌────────────────────┐
        │  VaultGuard.Common   │  数据层 / 加密 / 模型 / 工具
        └─────────┬──────────┘
      ┌───────────┼───────────────┐
      ▼           ▼               ▼
 Backup.Web   Endpoint.Server  Endpoint.Agent
 (系统一 B/S)  (系统二 控制端)   (系统二 终端服务)
```

公共库被三个应用工程共同引用，编译顺序由解决方案自动处理。

### 3.3 品牌信息单一来源

两套系统的登录页、关于页统一引用 `VaultGuard.Common.Branding` 的常量，
保证"登录界面展示公司名称与版权"这类展示要求只有唯一修改点：

```csharp
public static class Branding
{
    public const string CompanyName = "示例科技有限公司";
    public const string Copyright   = "Copyright © 2026 示例科技有限公司. All rights reserved.";
    public const string BackupProductName   = "虚拟化数据备份还原系统";
    public const string EndpointProductName = "终端安全准入与行为审计系统";
}
```

## 四、系统一：虚拟化数据备份还原系统（B/S）

### 4.1 架构

```
 浏览器 ──HTTP──► Backup.Web (ASP.NET Core + Razor Pages)
                        │
                ┌───────┴────────┐
                ▼                ▼
         SQLite(vaultguard-backup.db)   备份仓库(磁盘目录)
         主机/任务/备份点/日志          按时间戳存放的数据副本
                │
                └──► 备份引擎 ──► 本地路径 / UNC 共享(凭据) / [VMware 接口预留]
```

### 4.2 功能实现

| # | 功能 | 实现要点 |
|---|---|---|
| 1 | 登录界面展示品牌与版权 | 登录页底部固定版权行，取自 `Branding` |
| 2 | 备份 Windows 文件夹 | 选择文件夹/盘符，递归扫描入仓库 |
| 3 | 还原文件 | 浏览备份点 → 勾选文件 → 还原到原路径/指定路径 |
| 4 | 增量备份 | 快照清单比对（大小 + 最后写入时间 + CRC32），仅存变化文件 |
| 5 | 用账号密码添加 Windows 主机对象 | 主机表存凭据（AES-256-GCM 加密），访问远程 UNC 时 `WNetAddConnection2` 建立会话 |

### 4.3 数据表

| 表 | 关键字段 |
|---|---|
| `users` | id, username, password_hash, salt, created_at |
| `hosts` | id, name, address, os_type, username, password_cipher, remark, created_at |
| `backup_jobs` | id, name, host_id, sources, repo_path, mode(full/diff/incr), schedule, enabled |
| `backup_points` | id, job_id, started_at, finished_at, mode, file_count, total_bytes, status, manifest_path |
| `restore_logs` | id, point_id, files, target, operator, created_at |
| `op_logs` | id, actor, action, target, detail, created_at |

### 4.4 增量策略

1. **Full**：全量复制 → 生成清单 `manifest-<ts>.json`（相对路径 / 大小 / mtime / CRC32）
2. **Diff**：与**最近一次 Full** 的清单比对，复制变化文件
3. **Incr**：与**最近一次任意成功备份**的清单比对，复制变化文件
4. 还原时按"最近 Full + 后续 Diff/Incr"链式合成逻辑视图，对用户呈现为可选时间点

### 4.5 凭据加密设计

被管主机的访问口令一律经 `SecretBox`（AES-256-GCM）加密后落库，
密钥取自程序目录 `data/secret.key`（首次运行自动生成 32 字节随机密钥）。
数据库里不存在明文口令，可直接查库验证。

> 代价：`secret.key` 一旦丢失，已保存的口令全部无法解密，只能重新录入。
> 这是有意为之的取舍——把密钥与密文分离存放，避免"拖库即得密码"。

## 五、系统二：终端安全管理与审计系统（C/S）

### 5.1 架构

```
┌──────────────── 被管终端 ────────────────┐
│ Endpoint.Agent (Windows 服务, .NET 8)     │
│  ├─ 策略执行：注册表管控                   │
│  ├─ 文件审计：FileSystemWatcher            │
│  └─ 上报器：HTTP POST → 控制端             │
└───────────────┬──────────────────────────┘
                │ HTTP + AgentToken
                ▼
   Endpoint.Server (ASP.NET Core + Razor Pages)
   终端列表 / 策略下发 / 审计日志查询(按计算机、时间)
                │
                ▼
        SQLite(vaultguard-endpoint.db)
```

### 5.2 功能实现

| # | 功能 | 实现要点 |
|---|---|---|
| 1 | 登录展示品牌与版权 | 服务端登录页 + Agent 关于信息 |
| 2 | 禁用控制面板 | 同时写机器级 `HKLM\...\Policies\Explorer\NoControlPanel=1`（对全部用户生效，服务形态下的主落点）与用户级 `HKCU\...`（控制台形态补充）；下发即生效 |
| 3 | 禁用 USB 接口 | 注册表 `HKLM\SYSTEM\CurrentControlSet\Services\USBSTOR\Start=4`（需管理员） |
| 4 | 记录文件增、删、改操作 | `FileSystemWatcher` 监控指定目录，记录事件类型/路径/时间/用户；不含"读取"审计 |
| 5 | 按计算机对象、时间查询日志 | 查询页支持计算机 + 时间区间 + 事件类型筛选 |

### 5.3 策略下发与生效

```
控制端勾选策略 ──► 策略表落库 ──► Agent 心跳(30s)拉取 ──► 本地执行并回执
                                    └─ 立即生效，无需重启（注册表策略）
```

### 5.4 数据表

| 表 | 关键字段 |
|---|---|
| `agents` | id, hostname, ip, os_version, agent_token, last_seen, status |
| `policies` | id, agent_id, no_control_panel(bool), disable_usb(bool), audit_paths(json), updated_at |
| `audit_events` | id, agent_id, hostname, event_type(create/modify/delete/rename), path, occurred_at, received_at |
| `op_logs` | id, actor, action, target, detail, created_at |

## 六、关键设计取舍

| 取舍 | 选择 | 理由 |
|---|---|---|
| 数据访问层 | 轻量 SQL 映射，不引 EF Core | 表结构稳定、查询简单；省掉迁移与启动开销，单文件 exe 体积可控 |
| 口令存储 | PBKDF 式加盐哈希（`PasswordHasher`），不可逆 | 登录校验只需比对哈希；口令本身永不明文落库 |
| 主机凭据 | AES-256-GCM + 外部密钥文件 | 需要可逆（备份时要拿去连 UNC），故与登录口令走两套机制 |
| 文件审计 | `FileSystemWatcher` | 无需驱动、无 sysmon 依赖，开箱可用；代价是高负载目录下可能丢事件 |
| 策略生效 | 注册表 + 30s 心跳拉取 | 免重启即时生效；轮询间隔是"实时性 vs 控制端压力"的折中 |
| 发布形态 | 单文件 self-contained | 目标机不装 .NET，交付即用；代价是每套 70~90 MB |

## 七、已知边界

以下能力**明确不在**本工程范围内，相关接口层已预留或说明：

| 项 | 现状 |
|---|---|
| 虚拟机无代理备份 | `IVmBackupProvider` 接口预留，需具备有效许可的 vSphere/vCenter 环境方可实施，见 `04-虚拟机无代理备份接口说明.md` |
| 文件"读取"审计 | 未实现（`FileSystemWatcher` 只上报写类事件） |
| 打印 / 邮件 / IM / 网页管控 | 未实现 |
| 在线改密界面 | 未实现，需直接更新 `users` 表的 `password_hash` 与 `salt` 字段 |
| 多租户 / 集群部署 | 未实现，当前为单实例 SQLite |
