## 二、接口定义

文件：`src/VaultGuard.Backup.Web/Services/VmBackupProvider.cs`

```csharp
public interface IVmBackupProvider
{
    string ProviderName { get; }              // 提供方名称
    bool   IsConfigured { get; }              // 当前环境是否已配置可用后端
    string UnavailableReason { get; }         // 不可用原因（界面直接展示）

    IReadOnlyList<string> ListVirtualMachines();                       // 列举虚拟机
    VmBackupResult CreateSnapshotBackup(string vmName, string repoPath); // 创建快照备份
    VmBackupResult RestoreSnapshot(string vmName, string pointRef, string target); // 还原
}

public readonly record struct VmBackupResult(bool Success, string Message);
```

占位实现 `VmBackupProviderNotConfigured`：`IsConfigured = false`，
三个方法分别返回 `new VmBackupResult(false, ReasonText)`。

依赖注入（`Program.cs`）：

```csharp
builder.Services.AddSingleton<IVmBackupProvider, VmBackupProviderNotConfigured>();
```

## 三、未来对接路径（当目标环境具备有效许可时）

1. **新建实现类** `VmBackupProviderClient : IVmBackupProvider`，对接 vSphere Web Services API
   （或 vSphere Automation SDK）。
2. **配置来源**：连接地址、账号、口令（口令经 `CredentialStore` 加密存储，不落明文）。
3. **快照备份流程**：
   - 通过 `ListVirtualMachines()` 列举目标虚拟机；
   - 创建快照（静默快照优先）→ 导出/读取虚拟磁盘数据 → 写入本项目统一仓库目录
     （沿用 `{repo}/job-{jobId}/data/{时间戳}` 结构，便于与文件备份共用备份点与还原界面）；
   - 完成后删除临时快照，释放存储。
4. **还原流程**：按备份点定位落盘数据 → 写回目标数据存储/主机。
5. **切换实现**：仅需把 `Program.cs` 中的注册替换为新的实现类，界面与页面逻辑无需改动
   （页面通过 `IVmBackupProvider` 抽象交互）。
6. **实施前提**：使用方提供具备有效许可的 vCenter/ESXi 环境与可用测试账号；
   环境不具备时按设计约定豁免，本项不在本次范围。
